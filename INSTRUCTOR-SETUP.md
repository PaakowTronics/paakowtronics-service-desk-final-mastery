# Instructor Setup — PaakowTronics Service Desk

## Purpose

This package provides a reproducible Git repository for the **Git Essentials Final Mastery Challenge**.

The assessment is deliberately built around a business problem rather than a list of Git commands. The learner must discover the repository state, investigate other people's work, choose what belongs, handle an overlap, recover apparently lost work, and integrate one specific change.

## Package design

```text
final-mastery/
├── starter-remote.bundle       Clean Git history and branch source
├── setup.sh / setup.ps1        Build a fresh learner environment
├── prepare-recovery-test.*     Introduce the controlled recovery incident
├── reset.sh / reset.ps1        Rebuild the assessment from scratch
├── LEARNER-BRIEF.md            Handout for the learner
├── SCENARIO.md                 Instructor scenario
├── INSTRUCTOR-ANSWER-KEY.md    Private marking guide
└── assessment-repository/      Generated by setup; not distributed
```

The bundle is the only Git source shipped with the package. `starter-remote.git` is created temporarily by the setup/reset scripts and is not part of the package.

# 1. Prepare the Assessment

From the `final-mastery` directory run:

### Git Bash / Linux / macOS

```bash
./setup.sh
```

### PowerShell

```powershell
.\setup.ps1
```

The script creates:

```text
starter-remote.git/
assessment-repository/
```

The generated `assessment-repository/` is the learner's working repository.

## What the learner should see

The learner starts on local `main` with a clean working tree. The other prepared lines of work appear as remote-tracking branches under `origin/`.

The prepared history contains:

- `feature/knowledge-base` — useful but unrelated account-lockout documentation;
- `maintenance/queue-cleanup` — unrelated maintenance documentation;
- `feature/customer-portal` — relevant customer-facing work **plus one deliberately questionable policy commit**;
- `hotfix/portal-status` — a separate portal hotfix containing a procedure and a specific incident ticket.

Do not explain these roles to the learner in advance.

# 2. Give the Learner the Right Materials

Give the learner:

- the generated `assessment-repository/` directory;
- `LEARNER-BRIEF.md`.

The learner should begin with the repository's own:

```text
README.md
FINAL-MASTERY-CHALLENGE.md
```

Keep `INSTRUCTOR-ANSWER-KEY.md` private.

---

# 3. What the Instructor Should Observe

Do not rescue the learner with Git commands.

Observe whether the learner naturally:

- establishes state before editing;
- reads project documentation;
- inspects branch history rather than trusting branch names;
- distinguishes useful work from unrelated work;
- notices the questionable requester-role policy change;
- creates isolated work;
- predicts that overlapping changes may conflict;
- reads a conflict instead of blindly choosing a side;
- verifies before and after major operations;
- investigates apparent loss before attempting recovery;
- understands local branches versus remote-tracking branches;
- can identify one specific commit when management requests only one change.

A learner may use different valid Git operations. Mark the reasoning and resulting state, not command memorisation.

# 4. Recovery Incident

When the learner reaches Mission 6, ask them to stop and run the recovery preparation script from the package directory.

### Git Bash / Linux / macOS

```bash
./prepare-recovery-test.sh
```

### PowerShell

```powershell
.\prepare-recovery-test.ps1
```

If the learner's repository is not in the default location, the script accepts a repository path.

The script:

1. requires a clean learner repository;
2. records the current branch;
3. adds a small useful escalation note to `docs/incident-response.md`;
4. commits it as `docs: add temporary escalation note`;
5. moves the current branch back one commit;
6. leaves the old commit recoverable through the local reflog.

Do not tell the learner that reflog is the intended answer.

The script prints the hidden recovery commit ID for the instructor only.

If the learner has not maintained a clean working tree, stop and have them resolve that state before running the test.

---

# 5. Remote Behaviour

The learner's `origin` points to the generated local bare repository.

It is safe for the learner to inspect and push to this remote. It is not a public GitHub repository.

The assessment does not require a public network connection after the package has been prepared.

---

# 6. Reset for Another Learner

Reset deletes the generated learner repository and generated temporary bare remote, then recreates both from `starter-remote.bundle`.

### Git Bash / Linux / macOS

```bash
./reset.sh
```

### PowerShell

```powershell
.\reset.ps1
```

See `RESET.md` for the exact reset behaviour.

---

# Instructor Rule

Do not manually repair the prepared source history during normal assessment delivery.

If a learner repository becomes unusable, reset it and begin a fresh attempt. The bundle is the source of truth.
